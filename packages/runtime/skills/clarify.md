# Clarify (UX Writing)

Adapted from clarify. Use when writing or reviewing interface copy.

## Iron law

Every word must earn its place. Don't repeat what the UI already shows.

## Fix unclear copy

- Replace jargon with plain language for the audience
- Active voice, specific verbs ("Save changes" not "Submit")
- Error messages: what happened + what to do next
- Labels visible without relying on placeholder text alone
- Tone matches context (errors calm, success brief)

## Patterns

- Buttons: verb + object ("Create project", not "OK")
- Empty states: teach the next action, not "No data"
- Confirmations: name the consequence ("Delete 3 files permanently?")
- Avoid: "Successfully", "Please note", redundant headings

## In code

Update strings in components, i18n files, or constants — match the project's localization pattern.
